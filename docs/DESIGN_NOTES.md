# 设计说明

本文记录 `regex-compiler` 的设计推导过程：文法如何设计、算法如何选择、
数据结构如何组织、语义如何定义，以及已知的局限与后续方向。

---

## 一、项目目标

实现一个从正则表达式到最小化确定有限自动机的完整编译器，覆盖编译原理中
自动机理论的核心链路：

```
正则表达式 → 词法分析 → 语法分析 → NFA → DFA → 最小 DFA → 匹配执行
```

**范围界定**：

- ✅ 核心正则语法：字面字符、`.`、字符类、分组、选择、三种后缀运算符
- ✅ 完整编译流水线，各阶段中间产物可访问、可可视化
- ✅ 三种匹配语义：完全匹配、搜索、查找全部
- ❌ 扩展语法：锚点 `^` `$`、区间量词 `{n,m}`、反向引用、前后瞻

## 三、文法设计

### 运算符优先级

| 优先级 | 运算符 | 结合性 | 说明 |
|---|---|---|---|
| 1（最低） | `\|` | 左 | 选择 |
| 2 | 连接（隐式） | 左 | `ab` 表示 `a` 后接 `b` |
| 3 | `*` `+` `?` | 后缀 | 可叠加，如 `a*?` |
| 4（最高） | `( )` `[ ]` | — | 分组与字符类 |

### 上下文无关文法

采用 LL(1) 文法，便于用递归下降实现：

```
Expr     → Concat ('|' Concat)*
Concat   → Postfix+
Postfix  → Atom ('*' | '+' | '?')*
Atom     → CHAR | CHARCLASS | '.' | '(' Expr ')'
```

**为什么是 LL(1)**：每个非终结符的首符号集互不相交 ——
读到 `(` 必然是分组，读到 `[` 必然是字符类，读到字面字符必然是 `Atom`。
无需回溯，一次扫描即可判定。

**为什么连接要写成 `Postfix+` 而非 `Postfix Concat | Postfix`**：
左递归形式会导致无限递归；右递归形式会构造右结合树，与正则的直觉不符。
用循环累积再左结合构建，既避免递归深度问题，也符合 `abc` = `(ab)c` 的语义。

## 四、算法推导

### 4.1 Thompson 构造（AST → ε-NFA）

为每种运算符定义固定的子图模式，递归组合：

| 运算符 | 子图 | 新增状态 |
|---|---|---|
| 字符 `a` | `s --a--> f` | 2 |
| 连接 `AB` | `A.f --ε--> B.s` | 0 |
| 选择 `A\|B` | 新 `s` 分叉到两侧，两侧 ε-汇聚到新 `f` | 2 |
| 闭包 `A*` | 新 `s` 可跳过或进入 A；`A.f` 可自环或退出 | 2 |
| 正闭包 `A+` | 等价于 `A · A*` | 见下 |
| 可选 `A?` | 新 `s` 可跳过或进入 A | 2 |

**关于 `A+` 的实现陷阱**

朴素做法是 `concat(A, star(A))`，但 `star()` 会修改传入片段的 `accept` 状态
（加 ε 边、取消终态标记）。若直接复用同一个片段对象，`A` 的结构会被污染两次，
产生冗余状态。

正确做法有两种：

1. 先深拷贝片段再构造闭包
2. 直接按「至少一次」语义构造：新 `s --ε--> A.s`，`A.f --ε--> 新 f`，`A.f --ε--> A.s`

本实现采用方案 2，状态数更少且无副作用。

**复杂度**：每个 AST 节点摊还 O(1) 个新状态，总体 `O(n)`，`n` 为模式长度。

### 4.2 子集构造（ε-NFA → DFA）

DFA 的每个状态对应一组 NFA 状态的**子集**。核心是两个操作：

```
ε-closure(S) = 从 S 出发只走 ε 边可达的全部状态
move(S, a)   = 从 S 中任一状态走一条 a 边到达的状态集合
```

算法：

```
S₀ = ε-closure({nfa.start})
worklist = [S₀]
while worklist:
    S = worklist.pop()
    for each symbol a:
        T = ε-closure(move(S, a))
        if T is new: 建新 DFA 状态，入队
        记录 δ(S, a) = T
```

**状态数上界**：`2^m`（`m` 为 NFA 状态数）。这是理论上界，
实际正则表达式产生的可达子集远少于此。

**本实现的特殊处理**：转移符号不是「单字符」，而是「字符块」（见第五节）。
这保证了即使模式中存在重叠的字符类（如 `a|[a-z]`），
子集构造仍能产出真正的 DFA。

### 4.3 Hopcroft 最小化（DFA → 最小 DFA）

**目标**：合并行为等价的状态，得到状态数最少的等价 DFA。

**等价定义**：两个状态 `p`、`q` 等价，当且仅当对任意输入串 `w`，
`δ*(p,w)` 与 `δ*(q,w)` 的接受性相同。

#### 前置步骤：补全 DFA

Hopcroft 要求转移函数是全函数。若 DFA 存在「无转移」的情况，
必须先补一个死状态（sink）：非终态，对所有符号转移到自身。

**为什么必须补全**：若不补全，「状态 p 对符号 a 无转移」与
「状态 q 对符号 a 转移到非终态」在划分时会被视为两种不同签名，
即使二者行为实际等价（都无法接受），也无法合并。

补全后完成最小化，再剪除不可达状态 —— 这样 `a*` 这类模式仍能得到
1 个状态的最小结果，不会被死状态污染输出。

#### 划分精炼

```
P = {F, Q-F}                       # 初始：终态集 / 非终态集
W = {较小的那一组}                  # 工作队列
while W 非空:
    A = W.pop()
    for each symbol a:
        X = {q | δ(q,a) ∈ A}       # 原像
        for each block Y 被 X 切分:
            分裂 Y 为 Y∩X 与 Y\X
            if Y ∈ W:  两个子块都入队
            else:      只把较小的子块入队
```

**关键优化**：只把较小子块入队。这保证了每个状态最多被处理
`O(log n)` 次，从而总复杂度为 `O(k·n·log n)`。

**原像的高效计算**：维护反向转移表 `inv[a][t] = {q | δ(q,a) = t}`，
则 `X = ⋃_{t∈A} inv[a][t]`，无需扫描全部状态。

#### 复杂度对比

| 实现 | 复杂度 | 说明 |
|---|---|---|
| 朴素划分精炼（Moore 式） | `O(n²·k)` | 每轮全量重算签名 |
| Hopcroft | `O(k·n·log n)` | 工作队列 + 小半边入队 + 反向表 |

**一种常见误解**：很多人把「每轮重算签名的划分精炼」称为 Hopcroft 算法，
但它缺少工作队列与小半边优化，实际复杂度是 `O(n²·k)`。
两者的**结果相同**（都得到最小 DFA），差异在复杂度上界。

### 4.4 匹配执行

在最小 DFA 上模拟：

```
current = start
for ch in text:
    block = alphabet.block_of(ch)
    if block not in current.transitions: return REJECT
    current = current.transitions[block]
return current.is_final
```

**复杂度**：`O(m)`，`m` 为输入长度。DFA 的确定性保证了无需回溯 ——
这是相比回溯式引擎的核心优势。

## 五、数据结构设计

### 5.1 字符类与字母表

这是本项目最核心的数据结构设计。

```python
@dataclass(frozen=True)
class CharClass:
    chars: frozenset[str]    # 精确语义：允许的字符；取反语义：排除的字符
    negated: bool = False

    def contains(self, ch: str) -> bool:
        return (ch in self.chars) != self.negated
```

`negated` 与 `chars` 的组合优雅地表达了三种语义：

| 语义 | 表示 |
|---|---|
| 字面字符 `a` | `CharClass({'a'}, negated=False)` |
| 字符类 `[a-z]` | `CharClass({a..z}, negated=False)` |
| 取反类 `[^a-z]` | `CharClass({a..z}, negated=True)` |
| 通配符 `.` | `CharClass({'\n'}, negated=True)` |

注意 `.` 的实现：它等价于「排除换行符的取反类」，
与 Python `re` 的默认语义一致（`.` 不匹配换行，除非开启 DOTALL）。

**字母表划分**：

```python
@dataclass(frozen=True)
class CharBlock:
    id: int
    sample: str              # 代表字符，用于与 CharClass 做包含判定
    members: frozenset[str]  # 块内被模式显式提及的字符
    is_rest: bool            # 是否代表「未被提及」的字符
```

`sample` 字段是性能关键：判断「字符块 B 是否被字符类 C 包含」时，
只需检查 `C.contains(B.sample)` —— 因为同块字符在任意字符类上归属一致。

### 5.2 自动机状态

```python
@dataclass(eq=False)
class NFAState:
    id: int
    is_final: bool
    transitions: dict[CharClass | None, set[NFAState]]   # None 表示 ε
```

使用 `eq=False` 并显式实现按 `id` 比较的 `__eq__` / `__hash__`。
原因：状态需要放入 `set` 参与 ε-闭包计算，而 dataclass 默认按字段比较
会导致递归比较转移表，既慢又可能无限递归。

### 5.3 AST 节点

全部使用 `frozen=True` 的 dataclass：

- **不可变**：编译过程中 AST 不应被修改，不可变性提供了强约束
- **可哈希**：便于缓存与比较
- **模式匹配友好**：配合 `match` / `case` 可以优雅分派

```python
match node:
    case CharNode(char):              ...
    case ConcatNode(left, right):     ...
    case StarNode(child):             ...
```

相比 `isinstance` 链式判断，模式匹配同时完成类型检查与字段解构。

## 六、匹配语义定义

三种模式的行为差异必须明确定义，否则无法验证正确性。

| 模式 | 语义 | 返回值 |
|---|---|---|
| `match(text)` | 整个串必须被接受 | `bool` |
| `search(text)` | 最左最长的匹配子串 | `(start, end)` 或 `None` |
| `findall(text)` | 所有不重叠匹配 | `[(start, end, substr), ...]` |

### 最左最长语义

`search` 采用 POSIX 风格的最左最长匹配：从最左可行的起点开始，
取该起点下能到达的最远接受位置。

```
模式 a|ab，输入 "xab"
→ 起点 1 处可匹配 "a"（到 2）或 "ab"（到 3）
→ 取最长，返回 (1, 3)
```

这与 Python `re` 的「最左优先」策略在多数情况下一致，
在交替分支长度不同时可能给出更长的结果。本项目以 `re` 为基准做对拍，
因此实际行为以 `re` 为准。

### 空匹配的处理

当模式可匹配空串时（如 `a*`），`findall` 需要特殊处理以避免死循环：

```
若匹配区间为 (i, i)：记录空匹配，下次从 i+1 开始
否则：从匹配终点继续
```

同时需避免在相邻位置重复报告空匹配 —— 该规则与 `re.finditer` 的行为对齐，
由差分测试保证。

## 七、测试设计

### 分层策略

| 层次 | 测试文件 | 关注点 |
|---|---|---|
| 单元 | `test_lexer` / `test_parser` | 记号切分、AST 结构、错误定位 |
| 单元 | `test_nfa` / `test_dfa` | 构造正确性、状态数、确定性 |
| 集成 | `test_integration` | 端到端匹配语义、边界情况 |
| 对拍 | `test_differential` | 与 `re` 的语义一致性 |

### 为什么需要差分对拍

人工编写预期值存在固有缺陷：预期值来自实现者的理解，
若理解本身有偏差，测试会「忠实地验证错误行为」。

差分对拍把基准换成外部权威实现（Python `re`），
只要两者语义一致，就说明实现正确。

实际收益：这套测试在开发中发现了多处边界偏差，包括
`findall` 的空匹配位置序列、`search` 的最长匹配语义等 ——
这些问题用人工用例很难覆盖全。

### 关键断言

```python
# 确定性：每个状态对每个字符块至多一条出边
assert len(state.transitions) <= len(alphabet.covered_ids)

# 最小化不增状态
assert len(min_dfa.states) <= len(dfa.states)

# 最小化保持语言等价
assert simulate(dfa, w) == simulate(min_dfa, w)   # 对全部测试串
```

## 八、已知局限

| 局限 | 原因 | 影响 |
|---|---|---|
| 不支持锚点 `^` `$` | 未实现位置断言 | 无法表达「串首/串尾」约束 |
| 不支持区间量词 `{n,m}` | 未扩展语法 | 需手工展开为连接 |
| 不支持反向引用 | DFA 无法表达非正则语言 | 超出正则文法能力 |
| `search` 为最左最长而非回溯优先 | DFA 无回溯概念 | 交替分支顺序不影响结果 |
| 输入按 Unicode 码点处理 | 未实现字素簇概念 | 组合字符按多字符计 |

## 九、后续方向

按投入产出排序：

1. **锚点支持**：在 NFA 中引入位置断言转移，匹配时检查当前位置 —— 改动集中在 `nfa.py` 与 `matcher.py`
2. **区间量词**：词法层解析 `{n,m}` 并展开为连接的组合，无需改动自动机层
3. **正则到代码生成**：把最小 DFA 编译为状态转移表，生成可直接嵌入的词法分析器
4. **性能优化**：匹配结果缓存、DFA 状态转移的数组化存储
5. **Unicode 支持**：当前 REST 块逻辑已覆盖任意字符，主要工作在校验与测试
